Statistical exploration

1. Pipeline

Mnemonic → (BIP-39) → 512-bit seed → (BIP-32/44) → private key k
 → (secp256k1) → public key Q = kG → (Keccak-256) → 32-byte hash
 → last 20 bytes = address → (EIP-55) → checksummed address
StandardRole
BIP-39Entropy (128–256 bits) + checksum (1 bit per 32 bits of entropy), split into 11-bit groups = indices into a list of 2048 words → 12–24 words. The seed is PBKDF2-HMAC-SHA512 (2048 iterations, salt “mnemonic”+passphrase) → 512 bits.
BIP-32Hierarchical deterministic wallets: HMAC-SHA512 with key “Bitcoin seed” on the seed → master key (32 bytes) + chain code (32 bytes). Children (normal or hardened) are derived from a parent, so one seed produces unlimited keys.
BIP-44Path convention: m / purpose' / coin_type' / account' / change / index. For Ethereum: m/44'/60'/0'/0/0 (60 = ETH). Makes wallets interoperable.
secp256k1Curve y² = x³ + 7 over a 256-bit prime. Q = kG is easy; recovering k from Q (ECDLP) is not (~2¹²⁸ operations). Also used for signatures (ECDSA).
Keccak-256Hash: address = last 20 bytes of Keccak-256(Q without the 0x04 prefix, 64 bytes). It shortens and hides the public key until first use.
EIP-55Checksum hidden in letter case: compute Keccak-256 of the lowercase address (hex ASCII); the i-th alphabetic hex digit is uppercase if the i-th hash nibble is ≥ 8.

2. Concepts to distinguish

  • Generation vs derivation: generation = creating random entropy (the mnemonic, BIP-39); derivation = deterministic computation of new keys from an existing secret (BIP-32/44). Same input → same outputs.
  • Public-key cryptography: a pair (k, Q) with a one-way relation; used to sign/verify (secp256k1).
  • Hashing: keyless fixed-length function, resistant to preimages/collisions (Keccak-256; SHA-512 inside HMAC/PBKDF2).
  • Checksum: redundant data to detect accidental errors; it does not protect against attackers (EIP-55, and the checksum bits of the mnemonic).
  • Encoding: reversible representation with no secret (hexadecimal, word list, upper/lower case). It offers no security.

SHA-2/SHA-512 vs Keccak/SHA-3

SHA-2 is built with Merkle–Damgård (iterated compression). Keccak uses a sponge construction with a 1600-bit permutation: a completely different design, hence independent of any attacks on SHA-2. Ethereum adopted Keccak-256 before NIST finalized SHA-3; NIST changed the padding/domain-separation byte (Keccak: 0x01, SHA3-256: 0x06), so the outputs differ:

Keccak-256("") = c5d2460186f7233c927e7db2dcc703c0e500b653ca82273b7bfad8045d85a470
SHA3-256("")   = a7ffc6f8bf1ed76651c14756a061d662f580ff4de43b49fa82d80a4b80f8434a

Note: using a standard library's sha3_256 instead of Keccak gives wrong addresses.

4. Why several primitives?

  • BIP-39/32/44 → key management: human backup, derivation of many accounts, interoperability.
  • secp256k1 → private/public key relationship and signatures: only the curve gives public verification without revealing k.
  • Keccak-256 → short (160-bit), uniform address, and an extra layer between Q and the public.
  • EIP-55 → detect typos without changing the address format or length.

A single algorithm cannot do everything: a hash has no public keys or signatures; an elliptic curve neither compresses nor diffuses bits; a checksum is not secure. Separation of concerns: each piece is minimal, standardized and replaceable.

5. Statistical properties

  • Mnemonic entropy: uniform (from a CSPRNG). 12 words = 128 bits of entropy (+4 checksum); 24 words = 256 (+8).
  • PBKDF2/HMAC-SHA512 and Keccak: outputs indistinguishable from random, avalanche effect (1 input bit flips ~50% of output bits), collision resistance (160-bit address → birthday collision ~2⁸⁰).
  • Public key kG: no avalanche; it has algebraic structure ((a+b)G = aG + bG). The relevant property is ECDLP hardness, not avalanche.
  • EIP-55: ~15 letters on average → about 1 error in 2¹⁵ (roughly 30,000) goes undetected.

6. Suggested experiment

With MetaMask/Rabby/Rainbow etc., create a test wallet (never with funds or a real mnemonic): observe the word list (BIP-39), add more accounts (last index of the BIP-44 path), compare the address shown with upper/lower case (EIP-55), and confirm that the same mnemonic in another wallet reproduces the same addresses (BIP-32/44 determinism).
